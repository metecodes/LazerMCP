# One-sheet reference artwork and mechanical geometry

`create_from_reference(image_base64=..., primitives=[...], reference_markings=[...], format="both", parameters={...})` routes through the existing design/review pipeline, preserving explicit mechanical dimensions, finger-joint edges, slots, holes and mates. Images are engraving only. Named target panels must exist uniquely. Positions are explicit part-local millimetres; a centered logo uses the panel midpoint for x and a higher y for placement toward the top.

Example reference marking: `{"target_part":"top-panel","kind":"image","crop":[0.68,0.05,0.83,0.14],"ink_color":"yellow","x":60,"y":65,"width":30}`. This selects the Payas logo area in the supplied screenshot; actual placement must match the mechanical top-panel dimensions. A second marking can select the police artwork with crop `[0.195,0.730,0.30,0.85]`. Text and path markings may be supplied in the same list.

Without primitives, the tool remains a 2D tracer and cannot reconstruct mechanically valid joints from raster lines. Legacy reference conversion succeeds locally on the supplied image but retains only a few fused shapes; use image markings for detailed logos instead. The reported live internal error could not be reproduced from that image alone. A candidate mask sorting bug (NumPy arrays compared on equal scores) was fixed, and export/storage failure now returns success=false with REFERENCE_EXPORT_FAILED rather than propagating an unclassified export error. These changes do not prove that either was the reported live cause.

Both formats are generated by the same compiler call; physical fit and production authorization remain subject to the normal final gate.
